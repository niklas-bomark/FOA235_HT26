12.1 Introduction

In the previous lab, we introduced supervised learning and the basic predictive modeling workflow. We learned how to:

  1. identify an outcome variable;
  2. identify predictor variables;
  3. fit a linear regression model;
  4. compare the performance of different models.

The main problem with the modelling approach we took in the second half of Lab6 (apart from not inspecting the data properly before modelling) was that we used the same data to train the models as we used to evaluate their performance. This can lead to a problem called overfitting. A more complicated model will almost always be better at predicting the outcome for the same data set and observations it was trained on, but it might not be the best for predicting the outcome for new observations. In practical business applications, however, predicting new observations is the entire point of building machine learning models.

In this lab, we therefore divide the data into two parts:

  • training data — used to fit and develop models;
  • test data — used to evaluate how well the model predicts new, unseen observations.
Why do we need test data?

A model is fitted using the training data and will therefore tend to perform well on those observations. However, good performance on the training data does not necessarily mean that the model will perform equally well on new data.

The test data contain observations that were not used to fit the model. They therefore allow us to evaluate how well the model generalizes to new observations.

In this lab, we will use:

  • 70% training data;
  • 30% test data.

In addition to splitting the data, our modeling workflow will still include model comparison and model selection like we did in the previous lab. The new workflow will be:

Business problem → Split data → Fit candidate models → Compare models → Select one model → Evaluate on test data → Business decision

12.1.1 Learning objectives

After completing this lab, you should be able to:

  • explain the difference between training and test data;
  • fit several regression models;
  • calculate and compare training errors;
  • compare alternative models;
  • select a model based on training performance and other relevant considerations;
  • evaluate the selected model using test data;
  • translate model performance into a business recommendation.

12.1.4 Explore the Data

Before building models, we should understand the variables in our data and the relationships between them. One way to explore these relationships is to create a correlation matrix.

Correlation measures the strength and direction of the linear relationship between two variables. Correlation values range from -1 to 1:

  • values close to 1 indicate a strong positive relationship;
  • values close to -1 indicate a strong negative relationship;
  • values close to 0 indicate a weak or no linear relationship.

A correlation matrix allows us to quickly examine these relationships across several variables at the same time.

12.1.9 Model 3: A very complicated model

In the previous lab, the last model we built contained an interaction term between two of the predictors. Today, we will build a model that contains pairwise interactions between all of the predictors. We will treat this as a kind of “black-box” model. That is to say, we will use the output of the model to make predictions, but we don’t necessarily need to know exactly how these predictions are made.

Note that because of its size, running the code to fit the third model will take some time.

model3 <- lm(
  price ~ .^2,
  data = train_data
)

We will not inspect the coefficients for this last model.

12.1.10 Make Predictions on the Training Data

We now use each model to predict the observations in the training data.

pred1 <- predict(
  model1,
  newdata = train_data
)

pred2 <- predict(
  model2,
  newdata = train_data
)

pred3 <- predict(
  model3,
  newdata = train_data
)

Remember that these are the same observations that were used to fit the models. We are therefore measuring how well each model fits the training data.

12.1.11 Calculate Training Errors

Calculate the prediction errors for each model.

train_error1 <- train_data$price - pred1
train_error2 <- train_data$price - pred2
train_error3 <- train_data$price - pred3

12.1.12 Compare Models Using MSE

We compare the models using the Mean Squared Error (MSE).

\[MSE = \frac{1}{n} \sum (y_i - \hat{y}_i)^2.\]

A smaller MSE indicates that the predictions are, on average, closer to the observed values.

Training performance and model complexity

A model with a lower training MSE fits the training observations more closely. However, this does not necessarily mean that it will make better predictions for new observations.

As models become more flexible, they can fit the training data increasingly well. Eventually, a model may begin to fit patterns that are specific to the training observations rather than patterns that generalize to new data. This is called overfitting.

12.1.14 Evaluate the model using the test data

So far, we have only compared how well the three models perform on the training data. A more complex model will almost always have a lower training MSE, but that doesn’t necessarily correspond to a lower test MSE. Next, let’s see how the models perform on the test data, which wasn’t used to train the models.

# We first create predictions, but on the test data
pred1 <- predict(
  model1,
  newdata = test_data
)

pred2 <- predict(
  model2,
  newdata = test_data
)

pred3 <- predict(
  model3,
  newdata = test_data
)


# We calculate the errors
test_error1 <- test_data$price - pred1
test_error2 <- test_data$price - pred2
test_error3 <- test_data$price - pred3


# We calculate the MSE
test_mse1 <- mean(test_error1^2)
test_mse2 <- mean(test_error2^2)
test_mse3 <- mean(test_error3^2)

Add the new test MSE as a column to our comparison table.

# We create a new data frame comparing training and test MSE

12.1.15 Other considerations when selecting a model

There are several other aspects, apart from training- and test MSE, that could be important when selecting which model to implement in practice. Such as:

  • model complexity
  • interpretability
  • whether the improvement over simpler models is meaningful
  • cost of collecting data
  • computational costs.

Different aspects can be more or less important in different business contexts. For example, sometimes we are only interested in the predictions of the model, and other times we might want to be able to interpret its coefficients in order to understand more about the problem at hand.

12.1.18 From Model Evaluation to Business Decision

A model having a relatively low MSE does not automatically mean that the company should implement it. Management also needs to consider whether the predictions are sufficiently accurate to be useful for the business problem.

For example, consider:

  • How costly are prediction errors?
  • Is the prediction accuracy good enough for the intended decision?
  • Is the model understandable?
  • Is the required data available when predictions need to be made?
  • Are there observations for which the model performs particularly poorly?

This means that there are two related decisions:

Model selection

Which candidate model should we use?

and

Business decision

Is the selected model good enough to use?

12.1.20 Summary

In the previous lab we learned the basic idea of supervised learning. In this lab, we extended that idea to model comparison. We learned that different models can produce different prediction errors and that model complexity does not automatically produce better predictions for new observations.

We continued to use two different datasets:

  • training data are used to fit, develop, and compare models;
  • test data are used to evaluate predictive performance on new observations.

An important distinction is that a low training error tells us that a model fits the training observations well. It does not necessarily tell us that the model will make accurate predictions for new observations. The test error allows us to examine how well the model generalizes to data that were not used to fit it.

Finally, predictive modeling does not end when we calculate MSE. The final question is whether the model produces predictions that are sufficiently accurate and useful to support the company’s decisions.

In the next labs, we will continue to develop this predictive modeling workflow and introduce other methods.
